## Tenets (Unless you know better)

* Approving a code review means accepting responsibility for maintaining
  this code for the entire team.
* Code reviews serve as an audit trail for code changes.
* Two people must review a change before it is merged.

## Guidelines for Reviewers

* Ensure you understand the impact of this change on the overall system.
  When in doubt, ask questions.
* Check all code review artifacts for errors (test, coverage, and lint
  reports, links in the commit message, etc.).
* Verify that unit tests exist for:
  * Code that is difficult to understand;
  * Code that presents risk or could cause critical failures;
